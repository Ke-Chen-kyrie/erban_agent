# Erban Dashboard 首页导航重构设计

## 背景与目标

当前根路径 `/` 直接展示事件检测大屏，用户注册和用户管理通过大屏顶部入口访问。此次调整将三个功能在信息架构上拆开：根路径改为统一入口首页，用户从首页分别进入用户注册、用户管理或事件检测。

本次仅调整页面入口、导航和静态页面组织，不改变身份服务代理、事件接收、视频流、WebSocket、进程控制等后端接口和数据格式。

## 路由设计

| 路径 | 页面 | 说明 |
| --- | --- | --- |
| `/` | 功能首页 | 展示用户注册、用户管理、事件检测三个入口卡片 |
| `/register` | 用户注册 | 保留现有注册流程 |
| `/users` | 用户管理 | 保留现有管理功能 |
| `/dashboard` | 事件检测大屏 | 承载调整前根路径的完整大屏 |

现有 API、WebSocket、视频流和健康检查路由保持不变。根路径不再直接展示大屏，也不增加查询参数或前端模式切换。

## 页面与导航

新增独立的静态首页文件。首页延续现有深色、薄荷绿色视觉体系，主体展示三个等宽圆角卡片。每张卡片包含易识别的图标、功能名称、简短说明和进入提示，整张卡片均可点击并支持键盘焦点状态。

桌面端三个卡片横向排列；空间不足时自动换为单列，确保移动端可用。页面不加载事件状态、身份数据或视频流，仅承担导航职责，因此首页无需新增客户端 API 请求和错误状态。

事件检测大屏顶部删除用户注册和用户管理入口，避免功能继续附属于大屏。注册页、管理页和大屏中的品牌入口均指向 `/`；原有“返回大屏”文字统一改为“返回首页”。注册页和管理页之间可继续保留互相跳转的导航。

## 服务端组织

服务启动时分别解析首页和大屏静态文件：

- 根路径处理器返回新增首页文件；
- `/dashboard` 处理器返回原 `dashboard.html`；
- `/register` 和 `/users` 处理器保持不变。

自定义大屏 HTML 的既有能力继续生效：调用方传入自定义 `dashboard.html` 时，只影响 `/dashboard`，首页、用户注册和用户管理仍使用随包发布的静态页面。

## 兼容性

事件生产方和 Agent 使用的 HTTP/WebSocket 地址不变，因为它们不依赖根页面路由。浏览器书签若原先指向 `/`，升级后会进入功能首页，需要点击“事件检测”进入 `/dashboard`，这是本次需求要求的有意变化。

不提供从 `/` 到 `/dashboard` 的自动重定向，否则无法满足根路径作为三个功能入口首页的要求。

## 测试与验收

自动化测试应覆盖：

1. `GET /` 返回首页，并包含分别指向 `/register`、`/users`、`/dashboard` 的三个入口。
2. `GET /dashboard` 返回事件检测大屏。
3. 事件检测大屏不再包含用户注册和用户管理入口，并能返回首页。
4. 注册页和管理页仍可正常访问，导航中的首页链接正确。
5. 传入自定义大屏 HTML 时，内容出现在 `/dashboard`，而 `/` 仍返回随包发布的首页。
6. 运行现有完整测试集，确认身份代理、事件协议、视频和进程控制没有回归。

人工验收包括桌面宽度下三卡片横向布局、窄屏下单列布局，以及鼠标、键盘访问三个入口。

## 文档更新

README 的启动说明和兼容接口说明更新为：访问 `/` 进入功能首页，访问 `/dashboard` 直接进入事件检测大屏；其余公开接口保持现状。
